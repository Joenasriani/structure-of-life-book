01 / CLAIM

A programmer knows the rules because the programmer wrote the model. In life, we see the output and try to infer the rules.

02 / DEMONSTRATION

One output. Three possible structures.

If the visible result is the same, changing the hidden model changes what you should test—and therefore what you should do next.

OBSERVED OUTPUTA team keeps missing deadlines.

DISCRIMINATING TESTRemove one load constraint.

05 / SAMPLE

Three pages of the argument, reconstructed here.

STATE / S01

The state of something is not the same as our description of its state.

A programmer usually chooses which variables exist. A scientist studying reality does not. The world precedes the representation used to describe it.

REALITY ≠ MODEL OF REALITY
CONSTRAINT / S03

Removing a constraint from your model does not remove it from reality.

Physical, legal, economic, biological, social and assumed constraints require different interventions. The first task is not optimism or pessimism. It is classification.

Ω → constraints → Ωc
FAILURE / S09

Repeated correction can be evidence against the frame.

If downstream repair repeatedly fails, the producing structure may be upstream: a rule, interface, dependency, constraint or model assumption.

EXPECTED ≠ OBSERVED → TRACE DIVERGENCE
BOUNDARY

The book does not claim that life is software.

Structural correspondence, functional similarity and useful analogy are explicitly separated. Similar form does not prove identical mechanism, origin, intention or design.

SIMILARITY ≠ IDENTITY
